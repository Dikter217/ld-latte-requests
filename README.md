# LD LATTE · Requests Workspace

Веб-приложение для учёта заявок на автоматизацию бизнес-процессов, выполненное в рамках тестового задания LD LATTE. Стек: **React 19 + TypeScript + Vite + Supabase Auth + PostgreSQL + Row Level Security**. Интерфейс на русском языке, адаптирован для мобильных экранов.

## Возможности

| Функция | Реализация |
|---|---|
| Регистрация / вход / выход | Supabase Auth, email + пароль |
| Создание заявки | Название, описание и категория обязательны; статус всегда «Новая» |
| Редактирование | Название, описание, категория, статус |
| Список | Название, категория, дата создания, статус |
| Статусы | Новая → В работе → Завершена, можно менять в списке или форме |
| Поиск | По названию, без учёта регистра |
| Фильтр | Все / Новая / В работе / Завершена |
| Сортировка | Сначала новые или старые |
| Удаление | С подтверждением |
| Сохранность | Данные в PostgreSQL после перезагрузки и повторного входа |
| Разделение данных | RLS проверяет `auth.uid() = user_id` для SELECT/INSERT/UPDATE/DELETE |
| Мобильный интерфейс | Карточки вместо таблицы, выдвижное меню, адаптивные формы |
| UX | Пустые состояния, валидация, сообщения об ошибках, блокировка повторных сохранений |

**AI в этом проекте использовался для помощи в проектировании, написании компонентов, SQL и документации.** В приложении нет отдельного AI-чатбота или вызовов LLM API: задание требует систему учёта заявок, а не инференс модели. Платный AI API-ключ для запуска не нужен.

## 1. Настройка Supabase (примерно 10–15 минут)

1. Откройте [Supabase Dashboard](https://supabase.com/dashboard), создайте новый проект.
2. Дождитесь готовности PostgreSQL. Откройте **SQL Editor** → **New query**.
3. Вставьте содержимое файла `supabase/migrations/202611050001_create_requests.sql`, нажмите **Run**.
4. В **Authentication → Providers → Email** убедитесь, что регистрация по email разрешена.
5. Для реальной публикации оставьте подтверждение email включённым, добавьте адрес сайта в **Authentication → URL Configuration** (Site URL и Redirect URLs). Для очень быстрого локального теста подтверждение email можно временно отключить **только в тестовом проекте**, осознавая снижение безопасности.
6. Получите **Project URL** и **publishable key** (или legacy anon key) из **Project Settings → API** либо через **Connect**. **Никогда не используйте секретный `service_role`/`sb_secret_...` ключ в браузере!**

SQL включает RLS, явные разрешения SQL (GRANT/REVOKE), индексы, ограничения полей и триггеры `status = 'new'` при вставке и автоматического `updated_at` при изменении.

## 2. Локальный запуск

Требуется **Node.js 20.19+ или 22.12+** и npm. Docker **не нужен** для этого веб-приложения.

```bash
# Распакуйте архив и откройте папку проекта
cd ld-latte-requests
npm install

# Windows PowerShell:
Copy-Item .env.example .env
# macOS / Linux: cp .env.example .env
```

Откройте `.env`, замените примеры своими данными:

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_PUBLISHABLE_OR_ANON_KEY
```

```bash
npm run dev
```

Откройте `http://localhost:5173`. Если переменные не заданы, приложение покажет экран настройки вместо ошибки.

**Важно:** переменные `VITE_*` встраиваются в публичный JavaScript при сборке; поэтому туда допустим **только** publishable/anon key, никогда service-role/secret key. RLS обеспечивает защиту записей.

## 3. Проверки

```bash
npm test
npm run build
npm run preview
```

Проверьте сценарии в [`docs/acceptance-checklist.md`](docs/acceptance-checklist.md), особенно **двух разных пользователей**. Unit-тесты покрывают поиск, фильтрацию, сортировку, счётчики и валидацию. Полноценные интеграционные тесты Supabase Auth + RLS выполняются **после подключения реального проекта**, а не заменяются локальными тестами.

## 4. Публикация на Vercel

1. Создайте **новый приватный репозиторий GitHub**. Загрузите в него файлы проекта, **не добавляя `.env` и `node_modules`** (они уже в `.gitignore`).
2. Откройте [Vercel](https://vercel.com/new), импортируйте репозиторий GitHub.
3. Framework: **Vite**. Build Command: `npm run build`. Output Directory: `dist`.
4. В настройках проекта Vercel добавьте `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` в **Environment Variables**.
5. Нажмите **Deploy**. После первого успешного деплоя добавьте реальный адрес `https://your-app.vercel.app` в **Supabase → Authentication → URL Configuration → Site URL** и **Redirect URLs** (например, `https://your-app.vercel.app/**`). Это нужно для корректного перехода по письму подтверждения регистрации.
6. Если изменили переменные окружения в Vercel — запустите новый deployment.
7. Проверьте регистрацию, вход и запросы на реальном опубликованном URL.

`vercel.json` содержит SPA rewrite для обновления страницы по прямому URL.

## Что следует показать при сдаче

- Рабочий **публичный URL приложения** (логин требуется).
- Ссылку на **GitHub** с исходным кодом и README (доступ работодателю по согласованию).
- Скриншоты: форма регистрации/входа; экран заявок; создание и изменение статуса; поиск и фильтрация; мобильный экран.
- Видеодемо на 1–2 минуты: создать → редактировать → изменить статус → найти → обновить страницу → выйти/войти → увидеть те же данные.
- Отдельно продемонстрировать изоляцию пользователей A и B (RLS на уровне базы).

## Принятые технические решения

- **Supabase Auth** хранит учётные данные и сессии, не в самописной таблице.
- **RLS + явные SQL GRANTs** защищают заявки даже при обращении к REST API вне UI.
- **user_id** берётся из `auth.uid()` в базе; клиент не назначает владельца вручную.
- **Статус `new`** устанавливается серверным триггером при создании, а не только на клиенте.
- **Клиентская фильтрация** приемлема для тестового объёма; в production следует делать серверную пагинацию и поиск.
- **Без backend-сервера и секретных API-ключей**: браузерный клиент работает только с публичным ключом, доступ проверяет база.

## Ограничения и честный статус проекта

- Проект содержит рабочий исходный код и SQL, но **без ваших ключей Supabase, созданного проекта и Vercel deployment он не может работать онлайн**.
- SQL/RLS/реальная регистрация/деплой требуют проверки в вашем аккаунте — сейчас не проверены на живом Supabase.
- Загрузка ограничена **500 последними заявками пользователя**; нет серверной пагинации и realtime-синхронизации нескольких вкладок.
- Подтверждение email зависит от конфигурации Supabase; письма могут попадать в спам, а бесплатный стандартный SMTP имеет ограничения.
- Это MVP для тестового, не законченный корпоративный продукт: нет восстановления пароля, прав администратора, вложений и аудита действий.
