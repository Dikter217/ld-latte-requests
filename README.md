# LD LATTE — сервис заявок на автоматизацию

Тестовое задание на позицию специалиста по автоматизации.
 
Сделал веб-приложение, в котором можно зарегистрироваться, создать заявку на автоматизацию, отредактировать её и отслеживать статус.

**Работающий сайт:** https://ld-latte-requests.vercel.app

**GitHub:** https://github.com/Dikter217/ld-latte-requests

## 1. Что использовал

1. React 19, TypeScript и Vite — интерфейс приложения.
2. Supabase Auth — регистрация и вход.
3. Supabase PostgreSQL — хранение заявок.
4. Row Level Security (RLS) — разграничение доступа между пользователями.
5. Vercel — размещение сайта.
6. ChatGPT — помощь с кодом, SQL, структурой проекта и решением ошибок.

Отдельный AI API в приложении не используется. AI помогал именно в разработке.

## 2. Что умеет приложение

1. Регистрация по email и паролю.
2. Вход и выход из аккаунта.
3. Создание заявки с названием, описанием и категорией.
4. Автоматическое присвоение новой заявке статуса «Новая».
5. Редактирование заявки и изменение её статуса.
6. Поиск по названию и фильтрация по статусу.
7. Сортировка заявок по дате.
8. Удаление заявки с подтверждением.
9. Сохранение данных после обновления страницы и повторного входа.
10. Разделение заявок разных пользователей.
11. Адаптивный интерфейс для компьютера и телефона.

Статусы заявок: «Новая», «В работе», «Завершена».

Категории: «Бот», «Интеграция», «Отчёт», «Другое».

## 3. Как запустить проект

Для запуска нужен Node.js и npm.

### 3.1. Установка

Скачать проект, открыть PowerShell в папке с `package.json` и выполнить:

```powershell
npm.cmd install
```

На Windows использовал `npm.cmd`, поскольку PowerShell блокировал запуск `npm.ps1`.

### 3.2. Подключение Supabase

1. Создать проект на https://supabase.com/dashboard.
2. Открыть SQL Editor.
3. Выполнить SQL из файла `supabase/migrations/202611050001_create_requests.sql`.
4. Включить авторизацию по email.
5. Получить Project URL и Publishable key.

SQL создаёт таблицу заявок, ограничения для полей, индексы, триггеры и политики RLS.

### 3.3. Переменные окружения

Создать `.env` из `.env.example`:

```powershell
Copy-Item .env.example .env
```

Заполнить:

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_PUBLISHABLE_KEY
```

В `VITE_SUPABASE_ANON_KEY` нужно указать публичный ключ Supabase, не Secret key и не `service_role`.

Файл `.env` в репозиторий не загружается.

### 3.4. Запуск

```powershell
npm.cmd run dev
```

Приложение будет доступно по адресу http://localhost:5173/.

Проверка сборки:

```powershell
npm.cmd run build
```

Запуск тестов:

```powershell
npm.cmd test
```

## 4. Как устроено хранение данных

Все заявки хранятся в таблице `public.requests` в Supabase.

У каждой записи есть ID пользователя. В базе включена RLS с правилами для чтения, создания, изменения и удаления записей.

Проверка строится на `auth.uid()`: пользователь может работать только со своими заявками.

При создании новой заявки база автоматически устанавливает статус `new`. При изменении записи обновляется `updated_at`.

Защита реализована на уровне PostgreSQL, а не только через фильтрацию в интерфейсе.

## 6. Публикация на Vercel

Сайт опубликован:

https://ld-latte-requests.vercel.app

Для повторного развёртывания:

1. Импортировать GitHub-репозиторий в Vercel.
2. Выбрать Vite.
3. Указать Build Command — `npm run build`.
4. Указать Output Directory — `dist`.
5. Добавить `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` в Environment Variables.
6. Выполнить Deploy.
7. В Supabase → Authentication → URL Configuration указать адрес опубликованного сайта в Site URL и Redirect URLs.

В репозитории есть файл `vercel.json` для корректной работы маршрутизации.

## 7. Как использовал AI

Для разработки использовал ChatGPT. С его помощью подготовил структуру проекта, React-компоненты, запросы к Supabase и SQL для базы данных.

После генерации кода запускал проект сам и проверял основные сценарии в браузере.

Не всё заработало с первого раза.

1. Сначала Windows не распознавал `npm`. Установил Node.js.
2. PowerShell блокировал запуск npm-скрипта. Решил через `npm.cmd`.
3. При регистрации Supabase возвращал ошибку 404. Проверил запросы в инструментах разработчика браузера и нашёл лишний `/rest/v1` в адресе.
4. После исправления URL приложение показывало экран первоначальной настройки. Оказалось, что в `.env` дважды было написано `VITE_SUPABASE_URL=`.
5. После регистрации настроил подтверждение почты и адрес опубликованного сайта в Supabase.
6. При проверке выхода сначала не заметил кнопку. Посмотрел компонент Dashboard и нашёл её в нижней части бокового меню.

В итоге AI ускорил подготовку проекта, но настройку сервисов, запуск и проверку работоспособности выполнял вручную.
