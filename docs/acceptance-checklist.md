# Проверка тестового задания (LD LATTE)

**Перед проверкой**: выполнена SQL-миграция, в Supabase включена Email auth, в приложении заданы `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.

## Сценарии (проверять в браузере, не имитацией)

- [ ] Создать пользователя A (email+пароль); если включён Confirm Email — подтвердить письмо.
- [ ] Войти как A, создать заявку с названием, описанием, категорией «Бот».
- [ ] Новая заявка появилась в списке со статусом «Новая», датой создания.
- [ ] Изменить название, описание и категорию; после сохранения список обновился.
- [ ] Перевести заявку «В работе», затем «Завершена».
- [ ] Найти заявку по фрагменту заголовка; проверить поиск без учёта регистра.
- [ ] Отфильтровать список по статусу; вернуть «Все статусы».
- [ ] Перезагрузить страницу: заявка и статусы сохранились.
- [ ] Выйти и зайти повторно: данные сохранились.
- [ ] Создать второго пользователя B; проверить, что список B пуст.
- [ ] Под пользователем B нельзя читать, менять или удалять заявки A (проверить также через запросы к Supabase API, см. ниже).
- [ ] Под B создать собственную заявку; после возврата в A она не отображается.
- [ ] Проверить пустую форму, короткое название, длинное описание: показывается ошибка.
- [ ] Проверить ширину 375px: меню, таблица и диалоги пригодны к использованию.
- [ ] Проверить удаление заявки и отмену удаления.
- [ ] Проверить неверный пароль, отсутствие сети, повторное нажатие «Сохранить» при запросе.

## RLS: воспроизводимая проверка (настоящая база)

1. Создать отдельные учетные записи A и B.
2. Из A создать запись и сохранить её `id`.
3. В браузере B выполнить в консоли своего *локального тестового стенда* следующие запросы, заменив ID и используя текущий браузерный `supabase` клиент, если он доступен, **или** временно вставить код в локальную копию проекта:

```ts
const { data: shouldBeEmpty } = await supabase.from('requests').select('*').eq('id', 'A_REQUEST_UUID');
const { data: notUpdated } = await supabase.from('requests').update({ title: 'Попытка доступа' }).eq('id', 'A_REQUEST_UUID').select();
const { data: notDeleted } = await supabase.from('requests').delete().eq('id', 'A_REQUEST_UUID').select();
// shouldBeEmpty / notUpdated / notDeleted must each be []
```

4. Проверить, что запись A не изменилась и не исчезла.
5. Попробовать под B вставить `user_id: 'A_USER_UUID'` — операция должна завершиться ошибкой политики RLS.
6. При отсутствии сессии `anon` не должен иметь доступа к `public.requests`.

**Важно:** тесты безопасности выше требуют реального Supabase и не были выполнены при генерации файлов. Никогда не использовать service_role для проверки RLS — он обходит эти политики.
